Part 1 · 15 minutes

The fit / predict contract

One interface for hundreds of models.

scikit-learn is built around a promise. Every model is an object you create with its settings, fit on training data, and then predict or score on new data. A logistic regression, a decision tree and a neural network all look identical from the outside. That uniformity is why it is the standard tool for classical machine learning.

Defaults are decisions someone else made

Leave out solver and you get Adam, not SGD. Leave out alpha and you get a weight penalty of 0.0001. Leave out momentum and it is 0.9. None of these is wrong — but a result you cannot reproduce by hand is a result you cannot debug. Today we switch every one of them off on purpose, then switch them back on knowingly.

Part 3 · 15 minutes

Close, but not identical

97.6% by hand, 93.6% by library. Why?

Same architecture, same learning rate, same batch size, same number of epochs — and four points of accuracy apart. The difference is not a bug on either side. It is everything the settings did not pin down:

  • Starting weights. scikit-learn draws from a Glorot uniform range scaled to each layer's width; you drew from N(0, 0.1). Different starting points, different walks.
  • Batch order. Both shuffle every epoch, but from different random generators, so the 1,720 updates happen in a different sequence.
  • Small internals. Details such as how the loss is averaged and when the last partial batch is used.
The lesson in the gap

Two correct implementations of the same model, trained the same way, can differ by several points on 450 test images. A single run's accuracy is a sample, not a fact. Before claiming one model is better than another, ask whether the gap is larger than the difference a new random seed would make.
