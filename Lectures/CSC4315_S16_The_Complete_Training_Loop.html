Real data: 8 × 8 handwritten digits

Small enough for a laptop CPU, real enough to be proud of.

scikit-learn ships a dataset of 1,797 handwritten digits, each an 8 × 8 grid of grey levels from 0 to 16 — the same object as the grid you sliced in session 5. Flattened, each image is 64 numbers. We ask a question the session-14 network can answer without any new mathematics: is this digit even?

Two preparation steps, both with a reason. Divide the pixels by 16 so every input lies between 0 and 1 — session 19 shows what happens if you forget. And split before anything else, with a fixed seed, so the 450 test images are never seen during training.

Ten classes need a softmax output and a multi-class loss — one new idea too many for today. Even-versus-odd uses exactly the network, loss and backward pass you derived a week ago, so every line of today's code is something you have already understood.

Part 3 · 25 minutes

Epochs, mini-batches, shuffling

Four nested ideas, and the order they go in.

🔁

Epoch

One complete pass through the training set. Forty epochs means every image is seen forty times.

📦

Mini-batch

A small slice of examples — 32 today. Compute the gradient on the slice, take a step, move to the next slice.

🔀

Shuffle

A fresh random order at the start of every epoch, so batches differ each time and no pattern in the file's order leaks into training.

📉

Record

After each epoch, measure the full training loss and the test accuracy. These two curves are how you know what happened.

def train(lr, batch_size, epochs, seed=1):
    p = init_params()
    rng = np.random.default_rng(seed)
    losses, accs = [], []
    for epoch in range(epochs):
        idx = rng.permutation(len(X_train))                 # shuffle row numbers
        for start in range(0, len(X_train), batch_size):
            b = idx[start:start + batch_size]               # one mini-batch
            g = backward(p, X_train[b], y_train[b])         # session 14
            for k in p:
                p[k] -= lr * g[k]                           # session 9
        losses.append(bce(p, X_train, y_train))
        accs.append(accuracy(p, X_test, y_test))
    return p, losses, accs
Why mini-batches win

A gradient from 32 random images is a noisy estimate of the gradient from all 1,347 — but it costs a fortieth as much. Forty-two noisy steps per epoch beat one precise step, and the noise even helps a little, jostling the walk out of shallow dips. With 1,347 images and batches of 32 there are 43 updates per epoch.

🕳️
Shuffle the row numbers, never the arrays separately

Index X_train and y_train with the same slice of idx. Shuffling one without the other still runs, still produces a loss curve — and trains the network on images paired with the wrong labels. It is one of the four bugs in Lab 13.

Read the table the way session 9 taught you to read η. Too small is not wrong, only slow; too large is noisy and eventually diverges. The right choice is the largest rate whose curve is still smooth. And judge from the curves, not the last number: a run that ended well by luck on a jagged curve will not do so twice.

A number to be proud of, honestly

Guessing the more common class gets 46.7% of the test images right. Your network gets 97.6% — on images it has never seen, with a model you built from matrix multiplications and the chain rule. Always report the baseline beside the result.

Three questions

Answer before Lab 11.

Q1. How many parameter updates happen in 40 epochs with batch size 32? 43 batches per epoch (the last one has 3 images) × 40 = 1,720 updates.

Q2. The training loss after epoch 1 is higher than the starting loss of 0.69. Broken? Not necessarily. With η = 1.0 the first steps overshoot while the weights are tiny and uncoordinated. Look at the trend over epochs, not one point.

Q3. Why record test accuracy every epoch if we must not use the test set to make decisions? Today we only watch it, to learn what a training run looks like. Choosing the learning rate from it would contaminate it — session 22 introduces a separate validation set for exactly that job.
