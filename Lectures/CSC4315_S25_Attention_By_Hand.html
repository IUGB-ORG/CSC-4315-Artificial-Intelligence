Attention,
computed by hand

An embedding gives a word the same vector wherever it appears. But "bank" by a river and "bank" with a loan are not the same word in use. Attention lets every token look at every other token and build a new vector from what it finds. Today you compute one attention head on three tokens, with integers, on paper.

Part 1 · 10 minutes

Context changes meaning

Friday's vectors are fixed per word. In "the clinic needs medicine" we want the representation of needs to carry something of clinic and medicine. Session 13's network processed each example alone. What is missing is a way for positions in one sequence to exchange information, with the amount decided by the content itself.

Attention is a weighted average

For each token, compute a set of weights over all the tokens — how much to attend to each — then take the weighted average of their vectors. The weights come from dot products, so tokens whose vectors align attend to each other more.

Part 2 · 15 minutes

Queries, keys and values

Three roles, three learned matrices.

❓

Query

What this token is looking for. q = x·WQ

🔑

Key

What this token offers to be found by. k = x·WK

📦

Value

What this token hands over when attended to. v = x·WV

Scaled dot-product attention

Attention(Q, K, V) = softmax( Q·Kᵀ / √d ) · V

Score every query against every key, scale by √d, turn each row of scores into weights with a softmax, then mix the values.

Every piece of this is something you already own. Q·Kᵀ is session 8's matrix multiply. The softmax is session 11's sigmoid generalised to many options. The weighted sum is another matrix multiply. Dividing by √d keeps scores from growing with the vector length and pushing the softmax into its flat, saturated ends — session 19's problem again.

Part 3 · 30 minutes · on paper

One head, three tokens

clinic → needs → medicine, with d = 2.

TokenQueryKeyValue
clinic[1, 0][1, 0][2, 0]
needs[1, 1][1, 1][1, 1]
medicine[0, 1][0, 2][0, 3]
1
Scores for clinic. Its query [1, 0] against the three keys: 1·1 + 0·0 = 1, 1·1 + 0·1 = 1, 1·0 + 0·2 = 0.
2
Scale by √2 ≈ 1.414. 0.707, 0.707, 0.
3
Softmax. e0.707 ≈ 2.03 twice and e0 = 1; the total is 5.06; the weights are 0.401, 0.401, 0.198. They add to 1.
4
Mix the values. 0.401·[2, 0] + 0.401·[1, 1] + 0.198·[0, 3] = [1.203, 0.994]. The new vector for clinic now contains part of needs and part of medicine.
The full attention weights — every row sums to 1

medicine puts more than half its attention on itself — 0.576 — because its key [0, 2] is twice as long in the direction its own query [0, 1] points. Nothing decided that. A dot product was larger, so a score was larger, so a weight was larger.

The prediction question

Change the key for medicine from [0, 2] to [2, 0]. Before any arithmetic, predict which rows of the weights change, and which way their largest weight moves. Then open.

The key now points along the first axis, so it aligns with queries that have a first component. clinic ([1, 0]) now scores medicine highest: its row becomes [0.248, 0.248, 0.503]. medicine ([0, 1]) no longer aligns with its own key and shifts its largest weight to needs: [0.248, 0.503, 0.248]. needs ([1, 1]) scores 2 against the new key, exactly as before, so its row does not change at all.

Part 4 · 15 minutes

From one head to a transformer — recognised, not assembled

What you computed is one attention head. A transformer block, named part by part from the lecture diagram:

PartWhat it doesWhere you have met the idea
Token embeddings + positionsvectors for tokens, plus information about order — attention alone ignores ordersession 24
Multi-head attentionseveral heads in parallel, each with its own WQ, WK, WV, each free to track a different relationshiptoday, many times
Causal maskin a text generator, a token may only attend to earlier tokens — no peeking at the answersession 20's leakage, inside a model

Residual connections + normalisationadd each block's input back to its output; keep scales stable so deep stacks trainsession 19
Why we stop here

A full transformer is these blocks stacked a dozen to a hundred times, with learned matrices of millions of numbers. Building one does not fit in eighty minutes and would teach little beyond today. One head on three tokens is the idea; the rest is scale. On Friday you use a transformer somebody else built and trained.
